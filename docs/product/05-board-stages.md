Every sample project uses four board stages in this order: Brief, Build, Review, Handoff.

Brief captures the goal, audience, and intended deliverable. Build is where the example work is produced. Review is a check before the work is considered ready. Handoff is the final preparation and delivery stage in the fictional workflow.

Open the named project in the sidebar to reach Board and List. They display the same saved tasks, including tasks you add: Board groups them by stage, and List displays task rows. Select Brief, Build, Review, or Handoff in List to filter those rows. Filtering changes only what you see; it does not move a task. Before Create, Setup and Preview take the place of Board and List, and Preview filters unsaved sample tasks the same way.

A task in Handoff does not send a file, email a client, publish work, or charge anyone. Help center's Handoff answer explains that distinction. You can add a new task and move an existing task to another stage. Tasks cannot be renamed, edited, deleted, assigned, or reordered.

To create a task, choose New task. Give a name of 2 to 120 characters, an optional description up to 500 characters, and a stage; Brief is the default. The project holds at most 100 tasks.

To move a task, choose Move task, pick the task and its new stage, then save. You can also open a task and choose Move to another stage. A move keeps the task's title and details.

A change is saved only after the server confirms it; it then appears on Board and List and survives refresh. If an outcome is uncertain, check the board or use Retry on the unchanged form rather than starting a new one. A retry with the same request ID never duplicates or repeats a change.
